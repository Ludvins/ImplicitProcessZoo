# Security

Report security-sensitive issues privately rather than opening a public issue.
Use GitHub's private vulnerability reporting for the repository when available,
or contact the maintainer through the private channel listed on their GitHub
profile.

Include the affected version/commit, reproduction conditions, impact, and any
known mitigation. Do not include real credentials, private datasets, or
unredacted service tokens.

The supported branch is the current `main` branch. Research results and model
quality questions are not security vulnerabilities; use the normal issue
tracker for those. Dataset licensing or attribution concerns should likewise
be reported as documentation issues unless they expose confidential data.

See the repository-level `SECURITY.md` for the canonical reporting policy.
